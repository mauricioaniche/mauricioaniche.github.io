Requirements of a List

  • Should store an 'unlimited' number of elements
  • Should allow repeated elements
  • Should maintain the order of insertions
  • Should allow insertions in any part of the list
  • Should allow deletions and updates
  • Should be able to get elements by their index

Finding the empty space

public class OurArrayList {

    private Object[] elementData = new Object[10];

    public void add(int element) {
    	// we look for the first available position
        for(int i = 0; i < elementData.length; i++) {
        	if(elementData[i] == null) { // it's empty!
        		elementData[i] = element;
        		break;
        	}
    	}
    }
}

How fast is it?

  • Think about the number of times that 'for' will be executed.
  • Think about what happens to it when the array already contains many elements.
public class OurArrayList {

    	}

}

It is linear!

If we have 5 elements in the array, the for will iterate 5 times. If we have 5,000 elements in the array, the for will iterate 5,000 times. Thus, the execution time grows together with the number of elements.

We say this algorithm is O(n), where n is the number of elements in the array.

However, we know that Java does better!

What about we store the next available position?

Maybe we can store it in a variable...

Our array:

25 32 47              

next empty index = 0 -> 1 -> 2 -> 3 

public class OurArrayList {

    private Object[] elementData = new Object[10];
    private int size = 0; // track the next available position

    public void add(int element) {
        elementData[size] = element;
        size++;
    }
}

How fast is it now?

public class OurArrayList {

    private Object[] elementData = new Object[10];
    private int size = 0; // track the next available position

    public void add(int element) {
        elementData[size] = element;
        size++;
    }
}

It takes constant time!

If we have 5 elements in the array, it takes constant time. If we have 5,000 elements in the array, it takes the same constant time. Thus, the execution time does is always the same regardless of the size of the array.

We say this algorithm is O(1).

public void add(int element) {
    if(size == elementData.length) // it's full!
        resize();

    elementData[size] = element;
    size++;

private void resize() {
    Object[] newArray = new Object[elementData.length * 2];
    for(int i = 0; i < elementData.length; i++) {
        newArray[i] = elementData[i];
    }
    elementData = newArray;
}

Are we being 'naive' or is this how the real Java implementation works?

public boolean add(E e) {

private void grow(int minCapacity) {
	// overflow-conscious code
	int oldCapacity = elementData.length;
	int newCapacity = oldCapacity + (oldCapacity >> 1);
	if (newCapacity - minCapacity < 0)
		newCapacity = minCapacity;
	if (newCapacity - MAX_ARRAY_SIZE > 0)
		newCapacity = hugeCapacity(minCapacity);
	elementData = Arrays.copyOf(elementData, newCapacity);
}

How big should be the new array?

  • Us: oldCapacity * 2
  • Oracle Java 6: (oldCapacity * 3)/2 + 1
  • OpenJDK 8: oldCapacity + oldCapacity / 2

What you learned today?

  • Understanding data structures is fundamental for software engineers.
  • Data structures are different from each other (implementation, runtime).
  • ArrayLists use arrays internally. They take constant time for get() and add(), but not for addFirst().
  • We can use caching/pre-processing to speed up our algorithm.
  • There are no silver bullets!
