O teste automatizado é considerado um processo essencial para garantir a qualidade do software. No entanto, escrever e manter código de teste de alta qualidade é desafiador e frequentemente considerado de importância secundária. Para código de produção, muitos projetos de software industrial e de código aberto empregam revisão de código, uma prática de qualidade de software bem estabelecida, mas permanece a questão se e como a revisão de código também é usada para garantir a qualidade do código de teste.

O objetivo desta pesquisa é responder a esta pergunta e aumentar a nossa compreensão sobre o que os desenvolvedores pensam e fazem quando se trata de revisar o código de teste. Conduzimos métodos quantitativos e qualitativos para analisar mais de 300.000 revisões de código e entrevistamos 12 desenvolvedores sobre como eles revisam arquivos de teste.

Este trabalho resultou em uma visão geral das práticas atuais de revisão de código, um conjunto de obstáculos identificados que limitam a revisão do código de teste e um conjunto de questões que os desenvolvedores gostariam de ver melhoradas nas ferramentas de revisão de código. O estudo revela que a revisão de arquivos de teste é muito diferente da revisão de arquivos de produção, e que a navegação dentro da revisão em si é um dos principais problemas que os desenvolvedores enfrentam atualmente. Com base em nossas descobertas, propomos uma série de recomendações e sugestões para o design de ferramentas e pesquisas futuras.
